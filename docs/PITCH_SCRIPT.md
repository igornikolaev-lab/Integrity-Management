# Сценарій захисту проєкту IntegrityOS (≈ 3 хвилини)

**0:00–0:25 — проблема.** «Сьогодні дані про доброчесність у багатьох процесах збирають через анкети й чек-листи, а потім вручну зводять у звіти. Це створює затримки та ускладнює аналіз динаміки. Ми пропонуємо IntegrityOS — модуль, який об'єднує дані й перетворює їх на зрозумілий план дій».

**0:25–0:55 — Dashboard.** Показати індекс, чотири компоненти, графік двох циклів і сигнал про розбіжність: «Наш показник прозорий: 70% — групове анонімне оцінювання, 30% — контрольні індикатори; ваги компонентів сумують до 100%. Це свідомо демонстраційна, не офіційна модель НАЗК».

**0:55–1:25 — анкета.** Відкрити опитування, обрати категорію, показати 5 рівнів на шкалі 0–4: «Індивідуальні анкети не зберігаються в базі. Сума й кількість відповідей збільшуються атомарно, групи з менш ніж п'ятьма відповідями не показуються».

**1:25–1:55 — порівняння.** Відкрити порівняльну таблицю та чек-лист: «Це допомагає бачити розрив між тим, як люди оцінюють процес, і тим, які механізми формально впроваджено. Розрив — сигнал для перевірки, не доказ порушення».

**1:55–2:25 — рішення.** Відкрити рекомендації, натиснути «Прийняти», призначити робочу групу й дату: «Система не карає і не призначає винних. Вона пропонує дію, а керівник вирішує, приймати її чи ні. Далі є відповідальний, строк і статус, які можна звірити в наступному циклі».

**2:25–2:50 — ефект.** Звіти й експорт: «Одне оцінювання одразу живить Dashboard, динаміку, рекомендації й звіт. За прозорою моделлю економії часу для 41 відповіді потенційна економія становить близько 5 годин. Це припущення, не заявлений фактичний результат».

**2:50–3:00 — фінал.** «MVP запускається офлайн на Python і SQLite, має рольову модель, JSON API та Docker. Для застосування у відомчому середовищі потрібно посилити захист приватності та провести незалежну безпекову оцінку».

## Питання, які може поставити журі

**Чому не просто Google Forms?** Форма збирає відповіді; IntegrityOS пов'язує їх з контрольними індикаторами, динамікою та схваленим планом дій, і може розгортатись у закритому контурі.

**Це офіційний індекс НАЗК?** Ні, власна прозора демонстраційна методика за логікою рекомендацій НУОУ.

**Чи гарантована абсолютна анонімність?** Ні. MVP мінімізує ризик, не зберігає окремі анкети, приховує малі групи, але промисловий захист має також запобігати атакам за послідовними публікаціями агрегатів.

**Чи робить висновки ШІ?** Ні. Індекс та рекомендації побудовані на детермінованих правилах. ШІ використовувався на етапі допомоги з написанням коду й документації.

**Чи можна інтегрувати з відомчою ІС?** Так, як концепцію через JSON API та внутрішній шлюз, але конкретні відомчі системи й їхні права доступу має погодити власник ІС.

**Чому синтетичні дані?** Цього прямо вимагає завдання хакатону; так не розкриваємо жодних персональних або службових відомостей.
