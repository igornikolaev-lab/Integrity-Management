# Методика демонстраційного Integrity Index

## 1. Методологічна база

Рішення адаптує логіку чотирьох розділів анкет Додатка **В** до Рекомендацій НУОУ (2025): **Культура**, **Система**, **Підзвітність**, **Рівень зрілості доброчесності**. Для об'єктивнішого зіставлення використано **окремі, ілюстративно пов'язані** індикатори Контрольного чек-листа (Додаток **Б**). Це власна прототипна методика, **не офіційна методика НАЗК**. Перелік питань навмисно зменшено до восьми, тому модель не відтворює повний інструментарій з Рекомендацій.

## 2. Вхідні дані

- Кожне з 8 анонімних питань має п'ять градацій: 0=відсутньо/хаотично, 1=первинні дії, 2=визначено/впроваджується, 3=керовано/вимірюється, 4=постійно вдосконалюється. Шкала — узагальнена адаптація розвитку спроможностей.
- Бали переводяться з 0–4 у 0–100 множенням на 25.
- Об'єктивні статуси з чек-листа: «підлягає впровадженню»=0, «впроваджено частково»=50, «впроваджено повністю»=100. Статус **вносить аналітик**; сам по собі він не є перевіреним фактом, доки не зіставлено з доказами.
- Передбачено три широкі категорії: керівний склад, науково-педагогічний і цивільний персонал, курсанти/здобувачі.
- Для груп із `n < 5` не видається навіть точна кількість відповідей. Їхні бали **не включаються** до загального агрегату, щоб не відновити малу групу відніманням.

## 3. Формула

`S_i` — середнє значення **безпечних групових** відповідей компонента на шкалі 0–100; `E_i` — середнє оцінок інституційних чек-листів у відповідному компоненті.

```
C_i = 0.70 × S_i + 0.30 × E_i
Integrity Index = 0.30 × C_Культура
                + 0.25 × C_Система
                + 0.30 × C_Підзвітність
                + 0.15 × C_Зрілість
```

Ваги компонентів сумують до 100%. **70/30** обрано як демонстраційний баланс між сприйняттям процесів та фактом впровадження процедур. Ваги 30/25/30/15 підкреслюють значення етичної культури й підзвітності. Для реального впровадження ваги слід підтвердити методичним оцінюванням і тестом чутливості.

Усередині компонента ваги питань однакові. Якщо відсутній повний безпечний набір відповідей хоча б для одного компонента або для нього немає чек-листа, інтегральний індекс **не обчислюється**, замість довільної підстановки значень.

## 4. Шкала інтерпретації

| Значення | Демонстраційне найменування |
|---|---|
| 0–19,9 | Початковий |
| 20–39,9 | Формується |
| 40–59,9 | Визначений |
| 60–79,9 | Керований |
| 80–100 | Оптимізований |

Це **власні пороги MVP**, а не нормативні рівні CMMI/НАЗК. Кожен показник означає лише стан інституційної системи, а не оцінку конкретного керівника.

## 5. Розбіжності та рекомендації

`Δ_i = S_i − E_i`. Якщо `|Δ_i| ≥ 20` п.п., система позначає розбіжність. Вона може вказувати як на оптимістичні відповіді, так і на те, що формально впроваджені документи не працюють у практиці. **Сама розбіжність не доводить факт корупції**.

Для компонента формується рекомендація, якщо `C_i < 70` або `|Δ_i| ≥ 20`. Пріоритет: критичний для `C_i < 45` або `|Δ_i| ≥ 30`, високий для `C_i < 60`, інакше помірний. Кожна рекомендація містить опис, вимірюваний результат, посилання на числову умову; її схвалює керівник, який призначає відповідального, дату й статус.

## 6. Приклад стартового сценарію

Синтетичний осінній цикл: 11 + 14 + 16 = **41** безпечна відповідь, індекс **62,0/100**; окремі компоненти можуть давати різні значення. Зміна чек-листа або проходження анкети спричиняє новий розрахунок. Два демонстраційні цикли дозволяють перевірити динаміку. Всі значення — вигадані агрегати.

## 7. Відтворюваність і обмеження

Логіка у `model.py` (`compute`, `recommend`), тестові сценарії у `tests/test_app.py`. На MVP немає статистичних довірчих інтервалів, перевірки репрезентативності, валідизації питань на реальній вибірці чи підтвердження еталонності чек-листа. Перед використанням у реальній установі потрібна науково-методична експертиза.
