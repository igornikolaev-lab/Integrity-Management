# Інтеграційна схема та архітектура

## 1. Ключова архітектурна ідея

`Джерела оцінювання → HTTPS/JSON API → Assessment Engine → агреговані показники → Dashboard / Recommendations / CSV/JSON`. Реалізований MVP є автономним локальним модулем: `server.py` обслуговує API та офлайн вебінтерфейс; `model.py` — скоринговий модуль; `store.py` — SQLite / агрегування. У жодному компоненті не використовуються зовнішні мережеві залежності.

## 2. Карта можливих інтеграцій

| Потенційне джерело / споживач | Обмін | Що потрібно погодити |
|---|---|---|
| Відомча система документообігу | Індикатори виконання та статуси, ID документів | Власник ІС, правила ідентифікації документів, регламент доступу |
| LMS / система підготовки персоналу | Лише агреговане охоплення навчанням | Відсутність індивідуальних оцінок у публічному індексі |
| Система внутрішнього аудиту | Підтверджені індикатори та дати перевірки | Відокремлення службових відомостей, знеособлення |
| Відомчий портал / єдиний вхід | Модуль Dashboard, федерація ролей | Внутрішній IdP/SSO, взаємне TLS, журнали доступу |
| Сервіс аналітики / BI | Готовий JSON/CSV із безпечними агрегатами | Поріг вибірки, обмеження експорту, права споживача |

**Важливо:** це **потенційні категорії** відомчих ІС, не твердження про конкретні погоджені або існуючі API. Проєкт зараз не має фактичних інтеграцій із державними системами.

## 3. Конкретний технічний інтерфейс MVP

- `GET /api/config` — метадані, питання, рольові категорії й цикли.
- `POST /api/survey` — анонімне додавання до агрегату.
- `GET /api/dashboard` — автоматичний індекс, історія, групова аналітика.
- `GET/POST /api/evidence` — контрольні індикатори.
- `GET/POST /api/actions` — затверджені заходи розвитку.
- `GET /api/report.json`, `/api/report.csv` — експорт.
- `GET /api/audit` — журнал змін.

Деталі формату й ролей: [`API.md`](API.md).

## 4. Контур розгортання

Мінімальний сценарій — Windows/Linux/внутрішній віртуальний сервер із Python, SQLite, внутрішній DNS, доступ лише довірених клієнтів. Є `Dockerfile` і `compose.yaml`. Демоверсія слухає `127.0.0.1:8000` і навмисно не доступна з мережі за замовчуванням. Для інтеграції як модуля використовувати reverse-proxy на внутрішньому контурі; перед експлуатацією необхідно реалізувати промисловий IdP, TLS, аудит і безпекову оцінку.

## 5. Масштабування

Заміна SQLite на PostgreSQL, міграції схеми, окремий backend service, централізована індексація/спостережуваність, політики зберігання та публікації агрегатів по хвилях, розділення багатьох організацій (tenant isolation), конфігуровані питання/ваги/компоненти через версіоновані JSON-шаблони. У поточному MVP модель визначена в `model.py`; її можна змінювати у коді, але **адміністративний редактор конструктора анкет ще не реалізований**.
